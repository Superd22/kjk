To refresh the site after editing `template.html`, a `lead_<slug>.html` or `extra_<slug>.html` file, or `build_site.py`, run `hq/serve_local.sh`. It runs `build_site.py`, replaces the contents of the served folder with `hq/site`, and recreates the viewer symlinks and the standalone viewer page (made from `viewer/standalone.html`). It does not stop or start the server. Edits to `viewer/viewer.js` show on a browser reload without running the script, because the served file is a symlink. The build writes its time into the address of `viewer.js` (`viewer.js?v=<time>`), so the browser never keeps an old copy after the script has run.

The viewer data (`common.json`, `heads/`, `tex/` and `line.wav`) comes from `scan/trials-2026-11-18/kotor_viewer_export.py`. If the data folder moves, change the `DATA` line in `serve_local.sh`.

## Multi-page site (2026-11-19)

The artifact is now a small site, built into `site/` by `build_site.py`. Run it with `~/.claude/tools/likeness-fit/.venv/bin/python -I build_site.py` from this folder.

- `site/index.html` is the main page. It is `template.html` with the zone details taken out, the zone names in the grid linked to their pages, and a list of links to the eight zone pages.
- `site/zones/<slug>.html` is one page per zone. The slugs are forehead, brows, eyes, nose, cheeks, mouth, chin and jaw. Each page gets its steps and numbers from the grid in `template.html`, and its text and pictures from that zone's `<details>` block in `template.html`.
- `site/style.css` is the shared stylesheet, taken from the `<style>` block of `template.html`.
- `site/img/*.jpg` are the pictures, decoded from `blink.b64` and `gallery_pics.json`.
- The mouth page, like every zone page, has a comment `ADD NEW SECTIONS HERE` before its footer. New sections go there.

To change the site, edit `template.html` (or the script), rebuild, and publish `site/index.html` with the Artifact tool, passing the URL above as `url` and every file under `site/` except `index.html` in `files`, keyed by its path relative to `site/`. The older single-file `likeness-hq.html` is kept.

## Head viewer 2, the head creator preview (2026-11-19)

The page is at http://127.0.0.1:8765/viewer2/index.html. Its sources are in `viewer2/`. `index.html` holds the page and its style, `viewer2.js` the viewer, and `heads.js` the readable name, group and sex of each head. `fit.json` holds each head's fit distances for the default smoothed head, taken from `kotor-heads/fits_v6_smooth.fit.json` (written by `kotor_smooth_measure.py` with `KOTOR_RIGID=1`). `thumbs/` holds the portrait sheet. The loading, skinning and sound code in `viewer2.js` is copied from `viewer/viewer.js`, which it does not change.

- `serve_local.sh` stages it next to the old viewer. The scripts, `fit.json` and `thumbs/` are symlinks, and `index.html` is copied with a build number. After editing `index.html`, run `viewer2/restage.sh` or `serve_local.sh`.
- `viewer2/make_thumbs.sh` renders the 57 portraits with headless Chrome, from `index.html?thumbs=1`, in about 10 seconds. Rerun it when the default paint or the fits change.
- The default paint is the variant in `ours.json` marked `"default": true`, or else the last variant, which is the newest.
- An optional `viewer-data/shapes.json` adds a Shape choice. Its format is `{"variants": [{"id": "smooth", "label": "Smoothed fit", "dir": "shapes/smooth/"}]}`. The `dir` is relative to the data folder. Each head's file is `<dir>/<name>.json` and holds `{"pos": "<base64>"}`, the same as `ours.pos` in `heads/<name>.json`: little-endian float32, x y z for each of the `common.n` vertices, in the same frame. A file may also hold `bones` and `keyScale`, in the format of `ours`, when the shape moves the joints. A head with no file falls back to the current fit, and the page says so.
- `?mute=1` mutes the voiced line, and `?head=<name>` opens a head.
- A paint variant in `ours.json` may list `layers` (each with an `id`, a `label` and a `note`). The viewer then shows a switch for each layer, and its `file` holds `{layers}`, which the viewer replaces with a 1 or a 0 for each layer in order. `paint_heads` bakes every combination, so the viewer never computes paint itself. `?layers=101` sets the switches of the default paint. A head's entry may hold a `text`, which replaces the sentence about the base tone.
- The viewer welds the normals of the vertex copies on the layouts' seams (`weldGroups` and `weldNormals`), as the old viewer does.
- The right panel has four groups: Skin, Hair, Shape and Light. Each group has one hint line, `.hint`, which shows the `data-note` of the control under the pointer or the focus. Older paint versions sit under "Older versions" in the Skin group. The paint layer switches are built from the default variant's `layers` in `ours.json`. The recipe, the fit numbers and the "What is ours" list sit in the closed "Details" fold at the bottom.
